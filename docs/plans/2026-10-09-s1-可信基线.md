## Task 1：平台无关化 —— 清零 4 个既有失败 ✅ 已完成并验证

**问题**：`go test -tags wails ./...` 有 4 个失败，全部源于**同一类错误：把平台相关的行为写成了跨平台的断言**。

| 失败用例 | 现象 | 真实原因 |
|---|---|---|
| `fsutil.TestSanitizeFileNameRejectsUnsafeNames` | `"..\\..\\Startup\\evil.exe" must be rejected, got "evil.exe"` | `filepath.Base` 的语义随平台变 |
| `filesink.TestCreateRejectsUnsafeName` | `windows-style traversal must be rejected` | 同上（`Create` 调 `SanitizeFileName`） |
| `keystore.TestLoadOrCreateIsStableAndPersists` | `want 0600 got 0666` | Windows 不落实 POSIX 权限位 |
| `keystore.TestLoadOrCreateCreatesDirWith0700` | `want 0700 got 0777` | 同上 |

**关键判断：这里要改的是实现，不是测试。**

《架构设计书》§1.3 步骤 2 明确要求"**拒绝**含 `/` `\` `\x00` 的输入"；两条清洗用例独立地断言了同一件事。也就是说**实现偏离了契约**，而不是契约写错了：`SanitizeFileName` 把反斜杠的检查放在 `filepath.Base` **之后**，而 Windows 的 `Base` 已经把 `\` 当分隔符中和掉了（`..\..\Startup\evil.exe` → `evil.exe`），于是同一个对端报文在 Windows 接收端被接受、在 Unix 接收端被拒绝 —— **路径清洗是接收侧唯一的安全边界，它的裁决不该取决于收件人装的是什么系统。**

**改法**（`internal/infra/fsutil/safename.go`）：把反斜杠检查**提到 `filepath.Base` 之前**，在任何平台上都按路径分隔符拒绝。`/` 仍由 `Base` 中和（架构书步骤 1，且既有用例锁定该行为）。Base 之后的分隔符检查保留为**不变量断言**。

这与本仓既有的两处约定是一致的：发送侧的 `fileBase`（`internal/app/transfer_app.go:1131`）本来就同时剥掉 `/` 与 `\`，`SanitizeRelPath`（`internal/infra/fsutil/relpath.go:36`）也显式"两种分隔符都当分隔符"。**不会误伤正常发送端**：线上 `FileName` 由 `fileBase`/`filepath.Base` 生成，本就不含反斜杠；`rel_path` 另走 `SanitizeRelPath`，它在逐段调用本函数之前已经把 `\` 拆成段了。

密钥侧（`internal/adapters/keystore/keystore_test.go`）：`keystore.go` 的包注释自己就写着"Windows 不遵守 POSIX 权限位，属平台限制"，所以断言权限位的那部分本来就不可能通过。改为平台分支的 `posixPerms` 常量，并在 Windows 分支上**不断言权限位、但仍断言私钥确实落盘且非空** —— 不让用例退化成空跑。

**Files**
- Modify: `internal/infra/fsutil/safename.go`（检查顺序 + 文档注释与真实行为对齐）
- Modify: `internal/infra/fsutil/safename_test.go`（补 `docs\report.pdf`、`C:\Windows\...\hosts` 两个"看着正常"的带反斜杠用例，并注明这是平台无关性的钉子）
- Modify: `internal/adapters/keystore/keystore_test.go`（`posixPerms` 平台分支；顺手把 `dir + "/identity"` 改成 `filepath.Join`）

**验证（已实跑）**
```

go test ./internal/infra/fsutil/ ./internal/adapters/filesink/ ./internal/adapters/keystore/ -count=1
                                                      → 三个包全 ok

go test -tags wails ./... -count=1                     → 全绿
```

**未做**：没有引入 `golang.org/x/sys/windows` 去给私钥设真正的 Windows ACL。架构书已把"Windows 忽略 0600"记为知情接受的平台限制，收紧它是一次独立的安全改动（且要论证"标准库为何不够"），不属于本冲刺。

## Task 2：让红线检查真的会跑（关键修正：从 Makefile 搬进 Go 测试）

**问题（两个叠加）**

**改法**

**2a. 把三条红线改写成 Go 测试**（新增 `internal/archtest/arch_test.go`）

用标准库 `go/parser` + `go/ast` 解析 import，而不是 grep。理由不只是"更准"，而是本仓已经在这上面吃过亏：`Makefile:41-45` 的三条规则为了躲开注释里的 `"net"`/`"os"` 字样，写了一堆行首/行尾锚定的正则，而它们**只有靠注释反复警告才不会被后人改坏**；R2 更是只检查了 `adapters/net` 不引 `adapters/store` 这一条路径，与"适配器之间禁止互引"的语义相去甚远。测试用 AST 判定，天然没有注释误判，且能被 `go test ./...` 在任何平台上执行。

- **R1**：`internal/domain/**` 不得 import `net` / `database/sql` / `os` / 任何 wails 包（`domain/ports` 例外，与 `Makefile:42` 的口径一致）。

**2b. 新增 `.github/workflows/ci.yml`**

## Task 3：修 `list_epoch`（跨网段刷新失效）

**问题（已在代码中逐行核实）**

- `Broadcaster.epoch` 只在 `Start` 时置 1（`internal/adapters/net/udp/broadcast.go:110`），`Epoch()` 直接读它（`:101`），而 `LocalEpoch` 接线到它。
- `BumpEpoch()`（`:104`）的注释写着"本地目录变化时调用，使对端重新拉取"，但**全仓没有任何调用点**。
- 客户端把每个对端响应的 epoch 记进 `lastEpoch`，请求时带上（`internal/app/discovery_app.go:145-146`）。
- 服务端 `HandlePeerListReq`（`:154-166`）：`req.ListEpoch != 0 && req.ListEpoch == local` → **回空响应**。

于是：第 1 次拉取带 `list_epoch = 0` → 返回全量 ✅；第 2 次起带 `list_epoch = 1`，而本地 `local` 也是 1 → 相等 → **永远回空** ❌。后果见 `发现协议设计书.md:412-431`，同网段广播不受影响，所以现象是"跨网段新节点一直看不到"，而不是报错。

**为什么现有 e2e 抓不到**：`test/e2e/e2e_test.go:246-300` 每次都构造**全新的** `(本机, 种子)` 组合，恰好走的是"第 1 次"。

**改法（取设计书 §15.2 的选项 B：永远返回全量）**

`HandlePeerListReq` 忽略 `list_epoch`，无条件返回全量目录。核算：200 节点下一次响应约 12.8 KB、每节点 5 分钟一次 ⇒ 单种子出站 < 2 KB/s，与 ADR-011 的成本结论一致，**且没有正确性风险**。

不选选项 A（目录变化时 bump）的理由：A 需要一个"目录变化 → 递增 epoch"的跨模块信号，而"多处真相"正是本仓已经吃过两次亏的形态（见 Task 6）。把一条容易腐化的优化换成一条恒定正确、成本可忽略的行为，在这个规模下是净收益。

`ListEpoch` 字段**保留在线上格式里**（不破坏兼容），但要在协议注释里标明"当前实现忽略它"，避免它变成下一个"看着有用实则没人读"的字段（Task 7 的主题）。

**Files**
- Modify: `internal/app/discovery_app.go`（`HandlePeerListReq` 无条件回全量；`lastEpoch`/`setEpoch`/`epochOf` 的去留一并定夺 —— 若不再需要就删掉，别留死代码）
- Modify: `internal/domain/protocol/wire.go`（`ListEpoch` 的注释）
- Test: `internal/app/discovery_app_test.go`（**新增** —— `发现协议设计书.md:575` 指出本文件目前没有 DiscoveryApp 的独立单测）

**验收**
1. 新用例：**同一对节点连续两轮拉取，第二轮必须能拿到新加入的节点**。先写、先红（证明它抓得住这个缺陷），再改实现转绿。这是本 Task 的核心交付物 —— 没有它，"修好了"只是口头承诺。
2. 用例应走应用层（`DiscoveryApp` + 内存适配器），不依赖真实网络。

**量**：S

## Task 4：发现层收口

### 4a. UDP 层补 `nodeID == Fingerprint(pubkey)` 校验

**问题**：只有 TCP 握手校验身份与公钥的自洽性（`internal/adapters/net/tcp/handshake.go:141,222`）。UDP 侧用报文**自带的**公钥验签，却从不检查它与 `node_id` 是否自洽，于是目录里可以塞进"身份自相矛盾"的条目（`发现协议设计书.md:532-538`）。

**改法**：在验签**之后**补一行判定，与握手侧口径一致。两个站点：
- `internal/adapters/net/udp/broadcast.go:246-263`（`decodeAnnounce`，ANNOUNCE 与 BYE 共用）
- `internal/adapters/net/udp/seed.go:76-83`（种子探测路径）

`identity.Fingerprint(pub ed25519.PublicKey) NodeID`（`internal/domain/identity/identity.go:61`）就是握手侧用的同一个函数。

**验收**：自造一个密钥、声明**他人** `node_id` 的报文必须被丢弃（两个站点各一个用例）；同时确认合法报文不受影响。

**量**：S

### 4b. 目录容量上限与淘汰（让 `max_peers` 生效）

**问题**：`max_peers`（默认 512）在配置里存在但**没有任何读取点**（`发现协议设计书.md:551-553`）；目录无上限，配合 4a 未修时的污染面可以低成本灌大 DB。

**改法**：在 `ports.PeerDirectory`（`internal/domain/ports/ports.go:66`）上加一个方法（例如 `Prune(max int) (removed int, err error)`），两个实现都要落地（`internal/adapters/store/mem`、`internal/adapters/store/sqlite`），由 `internal/app/peer_app.go` 在 `Upsert` 之后按 `LastSeen` LRU 淘汰，组合根把 `max_peers` 注进去。

**注意（本仓已记录的教训）**：给 `ports` 里的接口加方法会**波及所有实现者，包括散落在测试文件里的测试替身** —— 只跑"受影响的包"会漏掉 `internal/adapters/wails` 里的替身，表现为 `go build` 通过而 `go test ./...` 全红（`docs/plans/2026-10-08-folder-transfer.md:21`）。因此每个 Task 的验证命令固定为全仓 `go test -tags wails ./... -count=1`。

**验收**：写入超过上限的条目后，`LastSeen` 最旧的那些被淘汰、总数不超过上限；`max_peers` 改动真的改变行为（而不是继续当装饰）。
