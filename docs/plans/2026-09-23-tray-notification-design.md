# 托盘常驻与新消息提示（2026-09-23 设计）

## 1. 背景与目标

现状：点窗口关闭按钮 = 进程退出。传输进行中、或只是想让它挂在后台时，这个行为很碍事；而且窗口不在前台时，新消息、传输失败都完全无声无息。

本次要做的：

- **关闭 → 收进系统托盘**（进程继续跑），托盘菜单里保留一个确定能退出的入口；
- **最小化 → 留在任务栏**（不改变系统默认语义）；
- **新消息 / 传输事件提示**：闪（任务栏按钮或托盘图标）+ 提示音 + **窗口标题里的未读数**，规则贴近 QQ；
- 两个开关（提示音、关闭到托盘）**落盘**，设置页与托盘菜单共用同一份状态。

## 2. 关键决策（均已确认）

| # | 决策 | 理由 |
| --- | --- | --- |
| 1 | 关闭 → 托盘；最小化 → 任务栏；提示覆盖两条路径 | QQ/微信的行为；把「关闭」与「最小化」语义分开后不容易让人找不到窗口 |
| 2 | 智能触发规则（见 §4 规则表） | 「有消息就响」会吵到无法忍受；「正看着的会话不打扰」是聊天软件的基本礼貌 |
| 3 | 提示音由代码合成并内嵌二进制 | 系统提示音走声音方案，很多人把系统音关了（表现为「有时没声音」）；自备音效有版权风险；合成音自包含、跨机器一致 |
| 4 | 开关一份状态、两个入口（设置页 + 托盘菜单），落盘 `config.toml` | 需要「临时静音」的场景很常见（开会/共享屏幕），翻设置页太慢；而重启后保持是基本预期 |
| 5 | 提示范围 = 新消息 + 传输完成 + 传输失败（传输类仅在窗口不可见时提示） | 失败比成功更值得提醒：传了一半挂掉而窗口收在托盘时，现在完全无从得知 |

**非目标（YAGNI）**

- **不做气泡通知**：Wails v3 beta.24 没有跨平台通知 API；Windows 下自己弹托盘气泡需要 `Shell_NotifyIcon(NIF_INFO)`，而 Wails 托盘的 HWND/uID 不可访问（另建一个托盘图标会变成两个图标）。真正要做需要引入 Windows Toast（要求注册 AppUserModelID 与开始菜单快捷方式），留作后续。
- 不做未读数的「按会话」提示（托盘只显示总数）。
- 不做开机自启、不做多实例合并。

## 3. 架构与分层

核心取舍：**「何时提示」必须能单测，所以把它从 Wails 里剥出来。**

```
┌─ main_wails.go（组合根，仍是唯一 import Wails 的文件）────────────────┐
│  托盘：app.SystemTray.New().SetIcon(...).SetMenu(...)                  │
│        OnClick → win.Show()/Restore()/Focus()                          │
│  win.RegisterHook(events.Common.WindowClosing) → e.Cancel() + Hide()   │
│  win.RegisterHook(WindowFocus) → 停闪 + 未读归零 + 标题复位            │
│  动作执行：win.Flash(on) / tray.SetIcon(图) / win.SetTitle(文本)      │
└───────┬──────────────────────────────────────────────┬───────────────┘
        │ ① 环境快照（可见/聚焦/当前会话）             │ ④ 动作
        ▼                                              ▲
┌─ internal/app/notify_app.go（L3 应用层，零 Wails 依赖）───────────────┐
│  决策器：事件 + 环境 + 设置 → 动作列表                                 │
│  规则表、3 秒节流、未读计数、静音开关、托盘不可用时的退化              │
└───────┬──────────────────────────────────────────────┬───────────────┘
        │ ② 事件（组合根订阅已有 bus 后转发）          │ ③ 播放声音
        ▼                                              ▼
  TopicChatReceived / TransferDone / TransferError   internal/adapters/notify/
                                                     sound_windows.go（winmm PlaySound）
                                                     assets/（wav + 两个托盘 PNG）
```

- **决策器不碰 Wails**：只吃「窗口可见？聚焦？当前会话是哪个？设置开着吗？」这几个值，吐「响一声 / 开始闪 / 停闪 / 窗口标题写什么」。规则表因此可以表驱动单测，不需要 GUI。
- **适配器之间零互引**（红线 R2）：事件桥（`adapters/wails`）与声音/素材（`adapters/notify`）互不认识，两边都由组合根接线。
- 决策器属于应用层，不 import `os`/`net`/Wails（红线 R1）；播放声音、读素材字节都是适配器的事。
- **决策器必须是并发安全的**（实施期补上的一条约束，原设计漏了）：调用它的来源有三个 —— 事件总线的同步派发（网络读循环、传输 worker 各自的 goroutine）、托盘闪烁计时器（600ms 一个 goroutine）、以及主线程上的窗口焦点钩子。内部状态一律加锁。
- **锁内不许调 `env()` / `set()`**：组合根注入的快照实现要读 Wails 窗口状态（内部 `InvokeSync` 会阻塞等主线程执行），而主线程自己也会回调决策器。持锁调用就是一条死锁路径：后台 goroutine 持锁等主线程，主线程等锁。因此快照取完再进锁。

## 4. 行为规则

| 事件 | 窗口隐藏 | 窗口可见未聚焦 | 聚焦 · 正是该会话 | 聚焦 · 其它会话 |
| --- | --- | --- | --- | --- |
| 新消息（入站） | 响 + 闪 | 响 + 闪 | **静默** | 响 + 闪 |
| 传输完成 / 失败 | 响 + 闪 | 静默 | 静默 | 静默 |

**「闪」的两种形态（互斥）**

- `win.IsVisible()` 为真 → `win.Flash(true)` 闪任务栏按钮（最小化时按钮仍在，可见但被盖住时同样有效）。
- 窗口已隐藏（收进托盘）→ 没有任务栏按钮 → **交替切换托盘图标**（正常 ↔ 带红点，约 600ms 一换）。Wails 托盘没有闪烁 API，换图标是唯一办法。

**停止与未读**

- 窗口重新获得焦点（点任务栏 / 点托盘 / Alt+Tab）→ 停闪 + 未读归零 + 标题复位为 `SwarmLink`。
- 未读计数由 Go 侧自算：按规则累加，聚焦即归零；**窗口标题**显示 `SwarmLink · 3 条未读`。**不依赖前端**上报。
- 未读数不用托盘 tooltip 承载 —— Windows 下它拿不到（见 §9 第 1 条）。窗口在任务栏时标题可见；收进托盘时只剩托盘的「有/无未读」两态（红点 + 闪烁）。

**悬停提示（QQ 式「谁发来的」）**

- 触发：鼠标停在托盘图标上（`NIN_POPUPOPEN`）→ 组合根现取 `NotifyApp.HoverText()` 并弹出原生提示框；移开即收（`NIN_POPUPCLOSE`）。**拉取语义**，不为每条消息推文本。
- 文案规则（全部在决策层，可单测）：
  - 无未读 → `SwarmLink`；
  - 有未读 → 每人一行 `名字：内容预览`，**最新的在最上**，同一人只占一行（显示最新那条），最多列 3 人；
  - 总未读 > 1 时末尾追加 `共 N 条未读`（只有一条时它是噪音）。
- 截断：名字 12 字符、内容 30 字符（按**字符**切，不是字节，否则中文会被切成半个字）；多行以 CRLF 交给控件。
- **图片消息的 content 是内联图 JSON**（几百 KB base64）：预览必须显示为 `[图片]`，绝不能把 JSON/b64 漏进提示框。
- 名字查不到（首见节点）→ 回落 `未知用户`，不出现「：你好」这种空名字文案。

**收到消息主动弹出（QQ 式气泡）**

- 触发：新消息到达、且属于「该提示」的场景（窗口隐藏 / 未聚焦 / 是别的会话）→ 除闪烁、提示音、标题计数之外，**直接把上面的悬停文案弹在托盘上方**，4 秒后自动消失。无需用户去悬停。
- **不弹的场景**：正看着该会话、自己发的消息、以及**传输事件**（传输事件的文案会退化成纯计数，在托盘上闪一个空气泡只会让人困惑）。
- 位置：悬停时按**光标**位置（光标就在图标上），主动弹出时按**通知区域**位置 —— 后者要自己找：`FindWindow("Shell_TrayWnd")` → `FindWindowEx("TrayNotifyWnd")` → `GetWindowRect`，取其正上方 120px；找不到（非标准 shell）退到主屏右下角；显示后按实测尺寸再夹一次进屏幕，避免越界被系统翻到任务栏下面。
- 连发多条：每次都弹出最新文案并重置 4 秒计时。
- 判断依据（为什么不是「等用户悬停」）：用户的诉求是「像 QQ 一样，消息来了就告诉我谁发的」，被动悬停只能算补救。
- 节流：一次提示后 3 秒内不再发声（连发十条只响一声），但未读计数与闪烁继续。

**关闭 / 退出语义**

- 窗口关闭按钮：`minimize_to_tray` 为真 → `e.Cancel()` + `win.Hide()` + 托盘图标闪两下（作为「我在这儿」的提示）；为假 → 放行，真正退出。
- 托盘菜单「退出」→ `app.Quit()`，**不受开关影响**（必须留一个确定能退出的入口）。
- 最小化按钮不拦截，保持系统默认。**开发模式（`wails3 dev`）的 Ctrl+C 退出路径不拦截**（`ShouldQuit` 保持未设置），否则开发流程会被堵死。

**失败模式（重点）**

- **托盘创建失败** → 记日志、不阻断启动，并且**关闭按钮退化为真正退出**。否则用户会遇到「窗口消失、右下角没图标、彻底关不掉」——最糟的失败模式。
- 声音播放失败 → 静默忽略，绝不弹错。
- 设置读写失败 → 沿用旧值继续跑。

## 5. 素材

### 5.1 提示音（代码合成，入库为资产）

`internal/adapters/notify/assets/notify.wav`：44.1kHz / 16-bit / 单声道 / 约 0.55s；音型「叮(1318Hz) → 咚(880Hz)」，每音带指数衰减与轻微尾巴；峰值压到 -6dBFS（不比系统提示音更响、不爆音）。用一次性工具生成后入库，不在构建期合成。

### 5.2 托盘图标（从应用图标派生）

`assets/tray.png` 与 `assets/tray-alert.png`（32×32 PNG）。

**关键决定：托盘图标使用「无文字版」。** 实测产品名文字在源图中高 39px / 500px = 7.8%，而 Wails 会把托盘图标渲染成系统小图标尺寸（`SM_CXSMICON`，标准 16×16），换算下来只剩约 **1.2px** —— 在托盘里就是一条糊白线，纯噪声。因此从素材里把文字区域用周围底色填掉，得到图形版托盘图标（16px 下看不出修补痕迹）。

`tray-alert.png` = 同图 + 右下角红点角标（16px 下红点直径约 5px）。

**已验证**：Wails 的 `SystemTray.SetIcon([]byte)` 接受 **PNG 或 ICO** 字节（`w32.CreateSmallHIconFromImage`，注释与实现一致），内部按系统小图标尺寸建 HICON。

应用图标（exe / 任务栏 / 安装包）不动，继续用带文字版。

## 6. 配置与设置页

```toml
[notify]
  sound = true              # 新消息 / 传输事件提示音
  minimize_to_tray = true   # 点关闭按钮时隐藏到托盘而不是退出
```

- Go：`config.Config` 加 `Notify` 段（默认都 true）；`SettingsService` 的 DTO 加两个字段 → 重新生成绑定。
- 前端：设置页（实际文件是 `views/SettingsView.vue`）加两个开关（复用现有 `label.check` 样式）。
- 托盘菜单用 `menu.AddCheckbox(...)` + `MenuItem.SetChecked(...)`（API 已核实）放同样两项；改动写同一份 `*config.Config` 并落盘。
- **托盘 → 设置页的刷新不能走事件总线**（实施期核实）：`eventbus.TopicConfigChanged` 只有常量定义，既没有发布者、事件桥也没有订阅它，发到总线上不会有任何人转发给前端。实现改为组合根直接 `app.Event.Emit(wadapter.EventConfigChanged, nil)`；前端在 `config:changed` 上自增一个 `ui.configRevision`，设置页 watch 它并**只回读那两个提示开关**（整份重载会把用户没保存的种子编辑冲掉）。
- 立即生效：配置快照是实时读的（托盘与设置页改的是同一个 `*config.Config`），关掉 `sound` 后决策器立刻不再发声，不需要重启。

## 7. 前端改动（仅两处）

1. `watch(chat.activeConvId)` → 调用新增的 `NotifyService.SetActiveConversation(convID)`（薄服务；不塞进 ChatService，语义清楚）。
2. 设置页的两个开关。

窗口是否可见/聚焦由 Go 侧直接读（`win.IsVisible()` / `win.IsFocused()`），前端不参与。

## 8. 测试与验收

### 8.1 单测（决策器，表驱动）

- 新消息 × 四种环境 → 断言动作（响 / 闪 / 静默）与未读增量；
- 传输完成 / 失败 × 两种环境（隐藏 / 可见）→ 只在前者提示；
- 节流：3 秒内两条消息只响一次，未读仍 +2（用 `FakeClock` 推进，不 sleep）；
- `sound=false` → 不产生发声动作；`minimize_to_tray=false` → 关闭动作返回「放行退出」；
- 聚焦 → 未读归零 + 停闪 + 标题复位；
- 自己发的消息（`direction=out`）永不提示；
- **托盘创建失败**（注入失败 tracer）→ 关闭动作退化为「真正退出」。

### 8.2 素材自检

`notify.wav` 是合法 RIFF/WAVE 且时长在 0.3–1.0s；两张 PNG 可解码、32×32，且 `tray-alert.png` 与 `tray.png` **确实不同**（防「闪动看不出变化」的静默失效）。

### 8.3 手工走查（Wails 侧无法单测）

**（已变更）** 曾有一个**仅 DEV 构建可见**的托盘菜单项「测试提示」（触发一次假的新消息提示）来辅助走查，功能落地后**已删除** —— 提示改为「收到消息主动弹出」之后，验提示不再需要假消息：单聊里发一条真消息就能同时看到闪烁、提示音、托盘气泡与窗口标题，而假消息造的未读会与真实状态混在一起（它造的未读会被焦点钩子清掉，容易误判成功能失效）。原因与影响见实施计划末尾的差异记录第 11 条。

因此下面这份清单请**用真实消息触发**（同一台机器上单聊发给自己以外的节点，或与另一个实例互发）。

1. 点关闭 → 窗口消失、托盘出现图标、进程仍在；
2. 点托盘图标 → 窗口恢复并聚焦；
3. 点最小化 → 留在任务栏（不隐藏）；
4. 隐藏时来消息 → 托盘图标闪 + 响一声；
5. 恢复窗口 → 停闪 + 窗口标题复位为 `SwarmLink`（初次进入前台时应能看到 `SwarmLink · N 条未读`）；
6. 最小化时来消息 → 任务栏按钮闪 + 响；
7. 可见但被盖住时来消息 → 闪 + 响；
8. 正看着该会话时来消息 → 不响不闪；
9. 正看着 A 会话、B 来消息 → 响 + 闪；
10. 提示音开关在设置页与托盘菜单双向同步（各改一次，另一处跟着变）、立即生效；
11. `minimize_to_tray=false` 时点关闭真的退出；托盘「退出」永远能退出；
12. 重启应用 → 两个开关状态保持；
13. 传输失败（隐藏状态下）→ 有提示音 + 闪；
14. **开发模式回归**：`start_dev.bat` 启动后 Ctrl+C 仍能正常退出。

### 8.4 回归

现有 Go 测试全绿、`npm run test`/`typecheck`/`build` 通过、`wails3 build -tags wails` 产出可运行。

## 9. 已知限制

- **Wails 的托盘 tooltip 在 Windows 上不可用，悬停提示改为自建（已实现）**：Wails 建托盘图标时会发 `NIM_SETVERSION` + `NOTIFYICON_VERSION_4`（`systemtray_windows.go:619`），MSDN 明确规定该模式下 "the standard tooltip is suppressed"，要重新打开需要 `NIF_SHOWTIP`；Wails 在 `setTooltip` 里确实带了该标志（`:512`），但它把 `NIM_MODIFY` 的失败**静默吞掉**（`:524` 直接 return），且对 `NIN_POPUPOPEN` 只做转发、不自行绘制 tooltip（`:475`）。实测（Windows 10 19045）：`tray.SetTooltip(...)` 后悬停**毫无反应**，连初始的 `SwarmLink` 都不显示。
  因此改用自建的 `internal/adapters/notify/hovertip_windows.go`：直接使用系统的 `tooltips_class32` 控件（圆角/阴影/DPI/字体全由系统负责，不自绘），由 `NIN_POPUPOPEN`/`NIN_POPUPCLOSE`（Wails 转发的 `OnMouseEnter`/`OnMouseLeave`）驱动。**仅 Windows 实现**，其它平台是空实现。
- **声音只有 Windows 实现**（`winmm` 的 `PlaySound`）；macOS/Linux 为空实现（不响、不崩）。要做需要各自平台的原生播放（`afplay` / `paplay` 或 GStreamer），本次不做。
- **托盘与闪烁的跨平台差异**：macOS 的托盘位于菜单栏、习惯上「关闭窗口」不等于退出；Linux 依赖 AppIndicator 支持。本次只保证 Windows 行为符合预期，其它平台不保证细节。
- **不做气泡通知**（原因见 §2 非目标）。
- 未读数是 Go 侧自算的「托盘计数」，与前端 per-conversation 未读可能短暂不一致（例如同一会话内前端已标记已读但窗口尚未获得焦点）——以窗口焦点为归零点，够用且可预期。
