# 共享文件弹框（独立窗口）设计

日期：2026-10-14
状态：已与产品确认并实现（`views/ShareDialog.vue` + `ShareApp.SetVisibility`）
参照：产品给的「共享 - 付成伟」截图（左选人 + 右文件表 + 一排工具栏）

## 1. 目标与非目标

**目标**：把「共享中心」从设置弹层的一个页签改成**独立弹框**，形态照参照页面：
左侧两级树选共享、右侧文件条目表格、顶部一排动作按钮 + 搜索框。

**参照页面与我们的模型差异**（决定了哪些照搬、哪些替换）：

| 参照页面 | 本项目 |
| --- | --- |
| 左侧按「单位 → 联系人」 | 左侧按「我的共享 → 每条共享」「联系人 → 他的每条共享」 |
| 一行 = 一个被共享的文件（含密码） | 一行 = 清单树里的一个**节点**（目录 / 文件 / 空目录） |
| 「设置密码」+「密码」列 | 换成「设置可见性」+「可见性」列（唯一真实生效的访问控制） |
| 「取消共享」作用于表格行 | 作用于**左树选中的那条共享**（表格行只是它的内容） |

**非目标**：口令/密码鉴权（后端没有鉴权层，做假密码是欺骗；另开一轮）、按人增减单个
文件（我们的粒度是整条共享 + 可见性）、重命名共享。

## 2. 界面结构

```
┌ Modal 1000×680 ────────────────────────────────────────────────┐
│ 共享文件          我发布 2 条 · 可见他人 3 条      [搜索框 ][查找] ✕ │  ← #head 槽
├────────────────────┬───────────────────────────────────────────┤
│ ▾ 我的共享 (2)      │ [共享文件][共享文件夹][取消共享][设置可见性] │
│   · 周报模板 指定人  │ [立即刷新]              …  [打开所在目录]   │
│   · 测试包   全部    ├───────────────────────────────────────────┤
│ ▾ 联系人 (1)        │ ☑ │ 名称      │ 大小 │ 时间 │ 可见性  │
│   · alice ●         │ ☑ │ ▾ docs    │64 KB │  —   │ 全部    │
│     · 测试包 3 项    │ ☑ │   └ a.txt │ 1 KB │ 3天前│ 全部    │
└────────────────────┴───────────────────────────────────────────┘
```

- 左栏固定 268px；组头可折叠（chevron），默认展开；联系人只列**确实发布了共享**的节点。
- 右栏是选中共享的**文件树**：目录在前、同类按名字；第一层默认展开、更深的收起。
  **没有「路径」列** —— 结构由缩进与展开表达，再铺一列重复路径只是噪音。
- 索引里只有文件与空目录，**中间目录由路径推导**（非空目录不占条目）。
  目录行成为可勾选对象：勾一个目录＝勾它整个子树（后端只认文件路径，因此勾选状态
  始终以条目路径列表为准，不存在「目录勾了但子项没勾」的中间态）。
- 空态三种：未选左树 → 引导文案；清单为空 → 「这条共享里没有文件」；共享方离线 →
  行内错误横幅 + 提示点「立即刷新」。

## 3. 交互与职责边界

| 按钮 | 作用对象 | 说明 |
| --- | --- | --- |
| 共享文件 / 共享文件夹 | — | 打开发布向导，选择器分别只允许选文件 / 只允许选目录 |
| 取消共享 | 左树选中的共享 | 仅「我的共享」；他人共享或未选时禁用 |
| 设置可见性 | 左树选中的共享 | 弹小弹层改 全部 / 指定人 / 仅群组（复用向导字段） |
| 立即刷新 | 左树选中的共享 | 我的共享 → RefreshIndex；他人共享 → 重拉清单 |
| 打开所在目录 / 下载所选 (N) | 右树的勾选集合 | 我的共享 → 定位本地（勾选里最浅的那条）；他人共享 → 发起 P2P 拉取 |
| 搜索框 | 右树 | 客户端过滤 名称/路径；输入即过滤，并临时展开全部目录 |

勾选目录后的下载是**前端展开**成其下全部条目路径再下发：后端一次最多受理 200 条
（`ShareApp.maxPullPaths`），超出时它会给出一句能照着做的错误，界面原样透出。

下载仍是**异步受理**：返回只代表共享方已受理，进度走 `transfer:*` 与传输列表（复用既有链路）。

## 4. 需要新增的后端能力（两处，都很小）

1. **`ShareApp.SetVisibility(ctx, shareID, vis)`**：可见性此前只能在发布时定，没有修改接口。
   实现＝取共享 → `Normalize` + `Validate` → 覆盖 `Visibility`/`UpdatedAt` → `repo.Upsert`
   → `afterChange`（重建摘要缓存 + 立即广播 + 推 `share:updated`）。
   配套：`ShareService.SetVisibility`（Wails）、前端 `shareSetVisibility`。
   **为什么必须重新广播**：可见性写在摘要里，对端靠它过滤；不广播的话「改成指定人」
   在对方列表里要等到下一轮周期通告（最长 45s）才生效。

2. **单文件共享的下载落点**：批次模型要求 relPath 至少两段（根名/文件名），而单文件共享的
   共享名默认就是文件名，于是落点成了 `<下载目录>/报告.pdf/报告.pdf`。
   改法：**由共享方决定根名** —— `HandlePullReq` 发现 `!sh.IsDir` 时强制根名为
   `共享文件`，落点变成 `<下载目录>/共享文件/报告.pdf`，多个单文件共享共用一个容器目录。
   为什么不改请求方：`RemoteShare`（摘要）里没有 IsDir，请求方**不知道**对方是文件还是目录，
   而这个名字决定的是对方磁盘上的落点 —— 只有知道的那一侧能定。不新增协议字段。

## 5. 前端结构

- 新增 `views/ShareDialog.vue`（独立弹框，复用 `components/Modal.vue`）；
  `ui.panel === 'share'` 时由 `App.vue` 渲染它，同时 `SettingsDialog` 不再承载共享页签，
  删除 `views/ShareCenterView.vue`（避免两份实现漂移）。
- 纯逻辑抽到 `utils/share.ts` 并单测（与 `utils/group.ts` 同一套路）：
  `buildShareGroups(mine, remote)`、`filterShareItems(items, query)`、
  `buildItemTree(items)`（推导中间目录）、`flattenTree(tree, expanded)`（按折叠状态拍平，
  并给出每行的勾选目标 `targets`）。
- 发布向导随弹框搬过去；`api/dialog.ts` 的 `pickShareTarget(kind)` 增加 `'file' | 'folder' | 'any'`。
