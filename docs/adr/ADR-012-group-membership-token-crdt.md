# ADR-012：群成员采用「发票 / 撕票」模型，退出权归本人、准入权归群主

**Status**：Accepted（设计已确认；实现计划见 `docs/plans/2026-10-11-group-membership-token.md`）
**来源**：`docs/plans/2026-10-11-group-membership-token-design.md`
**部分替代**：[ADR-003](ADR-003-group-chat-fanout.md) 中「成员状态仅由 owner 以 epoch 全量签名传播」的**成员同步部分**。
群级字段（`Name`/`State`）、扇出策略、20 人上限、群主权威**全部保留**。

## Context

`ADR-003` 把整张成员表压在**一个** owner 签名 + 一个 `epoch` 下，一致性规则简单，但装不下三个状态的**两个不同权威**：

- 「退出（`left`）」的权威是**本人**；
- 「加人 / 踢人（`active`/`kicked`）」的权威是**群主**。

因此**主动退出无处安放** —— 只能由群主代劳，这是硬伤而非 UI 问题。

同时，与该处相邻的两个缺口也被代码核实：

1. 成员变更只做一次「尽力而为的单播」（`broadcastMeta` 只发给 `active ∩ 在线`），
   且 `GroupApp` **没有 `Start()`**、不订阅 `peer.online`；`GROUP_MEMBERS_REQ/RESP` 有 handler
   **却没有任何发送端**；成员收到 meta 后**不转发**。→ **离线成员错过即永久错过**：
   被移出者仍以为自己还在群里；被加入者**本地连这个群都不存在**。
2. `HandleGroupMsg` 只检查 `msg_id`/`group_id` 非空，**不校验发送者是否为群成员**，
   被移出者仍能收发群消息。

## Decision

### 1. 成员资格 = 票 与 撕票

```
active(m)  ⟺  m 存在至少一张票，且该票未被任何撕票作废
```

- **群主加人 / 重新拉回** → **发一张全新的票**（从没出现过的票号）；
- **本人退出** → **撕掉自己当前那张票**（自签，本地立即生效，**群主离线也能退**）；
- **群主踢人** → **撕掉该成员当前那张票**（群主签）；
- 并发「退出 + 踢人」→ 两人撕的是**同一张票**，结果相同，天然幂等。

合并是**集合求并**，**没有任何「取最大版本」**，因此不需要时钟、不需要全局全序。

### 2. 票号必须来自群主的「群级」单调计数器

> `MintSeq` 是**群级**计数器（由群主单调递增），**绝不能是「每用户各自的计数器」**。

**理由（决定性）**：「加人是否生效」必须**不依赖群主是否知道对方的计数值**。
群级计数器保证「新发的票号恒大于此前发过的所有票号」，于是群主**无需读取任何对端状态**即可发一张必胜的票。

反例（每用户各自计数器的必然失败）：群 `{A(群主), B, C, D}` —
D 离线自行退出（`D.v=5, left`）；A 不知道 D 已自增到 5，按加人写 `D.v=3, active`；
D 上线逐用户取 `max(v)` → `v=5, left` ⇒ **群主把 D 拉回了却永久不生效**。
且并发时 `A: v=5,kicked` 与 `D: v=5,left` 会撞在同版号上，「取最新」对同版号无定义，
而 `mtime` 在无中心网络里不可信（各机时钟不同步）。

### 3. 紧凑表示：每成员三个整数

因为每次准入只发**一张**票、撕票总撕「当前那张」，所以任一成员**任一时刻最多一张活票**，
票集合与墓碑集合可等价压缩为三个整数，**不随操作次数增长，无需墓碑压缩**：

```
active(m)  ⟺  m.AdmitSeq > m.KickSeq  且  m.AdmitSeq > m.LeftSeq
```

> **判据必须是严格大于**：踢人/退出后 `KickSeq`（或 `LeftSeq`）恰好**等于** `AdmitSeq`（撕的就是那张活票）。
> 误写成 `>=` 会让**踢人当场失效**。

### 4. 合并规则

逐字段取 `max`（`LeftSeq` 取较大者的同时取其 `LeftSig`）；新成员直接并入。
**交换律 / 幂等 / 单调**三条性质以表驱动测试固化。因为每个字段都只有**一个写者**且该写者单调，
「取 max」与「取最新」等价。

### 5. 权威划分：群主签名册，本人签退出

| 内容 | 签名者 | 覆盖字节 |
|---|---|---|
| 群级字段 + 名册（含 `AdmitSeq`/`KickSeq`） | **群主** | `H(groupID \| name \| state \| mintSeq \| Σ(memberID, admitSeq, kickSeq))` |
| 本人退出 | **本人** | `H(groupID \| nodeID \| leftSeq)` |

`Name` **纳入**群主签名（改名是群主权力）；`DisplayName` **不纳入**（由各成员的 `ANNOUNCE` 维护，
纳入会让改昵称触发全表重签）。

### 6. 同步触发点（修缺口 1）

新增 `GroupApp.Start(ctx)`：

- **推送**：订阅 `TopicPeerOnline`，对「对方出现在我名册里」的每个群单向推送一次全量快照。
  **任一成员都能推** —— 这是「新成员本地压根没有这个群、无从发起拉取」的解法：他不需要发起；
  推送路径**按需拨号**（不是「只查现有会话」）：刚被拉进群的人本机没有连接，
  只查现有会话等于永远推不到他；
- **拉取**：订阅 `TopicPeerDiscovered` / `TopicPeerOnline`，摘要不一致时发 `GROUP_MEMBERS_REQ`
  （同样按需拨号，但先判「有无共有群」，避免给无关节点拨号）；抽查则不拨号；
- **抽查**：复用 1 秒节拍，**低频**（默认 60s）轮转比对摘要，兜住静默丢包。

新增 `GROUP_LEAVE 0x34`（本人签名的单点增量）。
**不复用 `GROUP_META`**：meta 是群主签名，退出是本人签名，权威不同 —— 混在一帧会让「谁能改这一帧」
再次说不清，而那正是本次要修的病根。

**名册广播的受众（`MetaAudience`）必须含「刚被移出的人」**，与群消息的 `FanoutPlan`
（只在群 ∩ 在线）刻意不同。只用 `FanoutPlan` 会得到一个极难解释的不一致：
**在线被踢的人收不到自己被踢**（他已不在 active 集合里，而广播目标正是 active），
而**离线被踢的人反而能靠上线推送得知** —— 同一动作的结果取决于当时在不在线。

### 7. 入站群消息校验成员资格（修缺口 2）

`HandleGroupMsg` 在落库前增加 `Active(senderID)` 判据；不满足则**丢弃但仍回 ACK**
（与既有「坏图片消息也回 ACK」同策略：不回 ACK 会让发送方无限重发）。
发送侧同时拒绝「自己已不在群」的发送（少走一趟网络，也避免界面上先出现
一条永远送不达的「发送中」）—— 两侧是配套的：发送侧少发、**接收侧兜底
（后者才是防伪造那一道）**，因为发送侧只依赖本地名册，随时可能落后。

## Consequences

**更好**

- 本人可**离线退出**（本 ADR 的唯一动因）；群主权威完整保留，**踢人不可自撤销**；
- 上线即对齐，消除「离线成员永久偏差」；
- 合并规则**无时钟依赖**，任意乱序 / 丢包下收敛；
- 存储 O(成员数)，无墓碑膨胀；摘要一致时不落库、不触发 UI 刷新。

**更差 / 接受的取舍**

- **内网可信前提下，任一成员都能向他人推送「你属于某群」**（`ADR-003` 同立场，v1.1 加密后收紧）；
- **群主永久离线则无法加人 / 踢人 / 解散** —— 与现状一致，**未变差**；而退出不再受此限制，属净改善；
- `RosterSig` 布局变更，**存量群需重签一次**（启动时由群主自动完成，无需用户操作）；
- 「被踢者自助回群」**明确不做**。

## 被否决的替代方案

| 方案 | 否决理由 |
|---|---|
| **每用户一个递增版本号 + 取最新** | 两个写者共用一个计数器 ⇒ 群主拉回可能永久不生效（见 Decision §2 反例）；同版号冲突无定义；时钟不可信 |
| **完全去中心 gossip（去群主权威）** | 踢人可被自我撤销，需另立仲裁规则，与 ADR-003 冲突 |
| **退出 = 向群主发请求** | 群主离线即无法退出 |
| **保留 epoch 全量快照 + 仅叠加自签 left** | 可解决退出，但「拉回」仍需群主递增 epoch —— 因为 epoch 与 `leftSeq` **不同源、不可比**。保留为**降级选项** |
