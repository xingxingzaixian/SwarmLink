# 开发与部署指南

这份文档只回答四个问题：**怎么把项目跑起来、怎么改、怎么测、怎么交付到现场**。

设计原理不在这里 —— 协议、数据模型、领域建模的权威版本是
[`plan/架构设计书.md`](../plan/架构设计书.md)，取舍背景见 [`adr/`](adr/README.md)，
实现规格见 [`superpowers/specs/`](superpowers/specs/)。

---

## 1. 环境准备

| 依赖 | 版本要求 | 用途 |
|------|----------|------|
| Go | **≥ 1.26**（以 `go.mod` 为准） | 后端构建与测试 |
| Node | **≥ 24**（见 `frontend/.nvmrc`） | 前端构建；测试直接用 Node 跑 `.ts`，依赖类型擦除 |
| `wails3` CLI | **v3.0.0-beta.29**，且**必须用与本机相同的 Go 版本编译** | 桌面端构建 |
| NSIS（`makensis`） | 任意较新版本 | 仅打 Windows 安装包时需要 |

```powershell
go version
node -v
go version (Get-Command wails3).Source    # 两行输出必须一致，不一致见 §8
```

> Windows 上通常没有 `make`。本指南给出的 `make` 命令都标了等价的原生命令，
> 没有 `make` 时直接照后者执行即可 —— 包括架构红线测试，它就在 `go test` 里。

## 2. 本地开发

```powershell
.\start_dev.bat                 # Windows，默认端口 9245，参数透传给 wails3 dev
.\start_dev.bat -port 9250      # 换端口
```

改 Go 和前端都会热重载。

**只调前端**时不必起 Go 后端：

```powershell
cd frontend
npm install
npm run dev          # 无后端时自动进入 mock 模式，界面照常可点
npm run typecheck
npm run build
```

**改了服务导出方法**（`internal/adapters/wails/services.go`）后，需要重新生成前端绑定：

```powershell
wails3 generate bindings -f "-tags wails" -clean .    # 或 make bindings
```

`frontend/bindings/` 是**入库**的，前端因此可脱离 Go 工具链构建（CI 的 frontend job 依赖这一点）。它由工具生成，不要手改。

## 3. 构建与打包

```powershell
.\scripts\pack.ps1 windows build      # 出 bin\SwarmLink.exe
.\scripts\pack.ps1 windows package    # 出 NSIS 安装包（需要 makensis）
```

有 `make` 的环境等价于：

```bash
make gui          # 生成绑定 + 构建 → bin/SwarmLink
make package      # 出安装包
```

`pack.ps1` 做三件容易被漏掉的事，所以**不要绕过它直接 `wails3 build`**：

1. 强制导出 `EXTRA_TAGS=wails`。漏了这个 tag，产物是一个 **2.4 MB 的占位程序**，
   但它照样能打包成安装包并显示"构建成功" —— 本项目最隐蔽的失败模式。
   脚本末尾会按产物体积再挡一次。
2. 把当前 Go 的 `GOPATH\bin` 提到 PATH 最前，避免用到旧版本 Go 装的 `wails3`。
3. 处理 `GOTOOLCHAIN` 与多版本 Go 下 `GOROOT` 不一致的问题。

**入口**：`main_wails.go`（build tag `wails`），唯一接触 Wails API 的文件。
服务层与事件桥是零 Wails 依赖的纯 Go，因此 `go build ./...` 与 `go test ./...`
**不需要 Wails 工具链**；未启用 tag 时根目录无文件可编译，构建会跳过（也不会再悄悄产出占位程序）。

**换图标**：替换 `build/appicon.png` 后重新构建。DMG 相关资源仍为 Wails 模板默认值。

## 4. 测试

```powershell
go test ./...                    # 全部测试，含三条架构红线与 gofmt 闸门
```

`make` 用户另有：

| 命令 | 作用 |
|------|------|
| `make test-e2e` | 端到端（含跨网段收敛） |
| `make test-scale` | 20 节点规模验证 |
| `make test-fuzz` | 协议畸形输入 |
| `make lint-arch` | 架构红线 + 格式闸门 |
| `make ci` | 等价于 CI 的一条命令 |

测试矩阵：

| 层级 | 范围 | 目标 |
|------|------|------|
| 单元 | `domain/**` | 覆盖率 ≥ 80% |
| 组件 | 协议编解码 / SQLite 迁移 | 无 panic、迁移可重入 |
| 集成 | 2 节点握手与会话管理 | 主链路通过 |
| E2E | 3~4 节点全链路、跨网段收敛 | 通过 |
| 规模 | 20 节点 | 目录同步正确、常驻连接 0 |
| 前端 | 类型检查与构建 | 通过 |

测试用 `FakeClock` 控制系统时间：心跳超时（30 s）、TTL（300 s）、空闲回收（5 min）
若用真实时间，一个用例要跑几分钟；有了 `Clock` 接口全部是微秒级。

## 5. 部署到现场

**部署前先在现场机器上跑一次自检**：设置 →「部署自检」→ 运行自检。
它会真实探通每个种子、拉取目录，并给出 P-1 / P-2 的结论。

| # | 前置条件 | 不满足的后果 |
|---|----------|--------------|
| **P-1** | 任意两网段的种子 IP 之间**可 TCP 直连**（三层路由可达，非 NAT 隔离） | 跨网段发现与消息全部失效 |
| **P-2** | 各网段使用**不重叠的地址段**（不得都是 `192.168.1.0/24`） | 目录中出现 node_id 不同、IP 相同的条目，跨网段寻址崩溃且极难排查 |

> P-2 不是理论风险：「多个厂区各用一个 `192.168.1.0/24` 再靠 VPN 互联」是内网最常见的形态之一。

另外两项现场必做：

- **防火墙放行** TCP/UDP 端口；
- **种子机器固定 `udp_port`**（关闭端口自动回退），否则跨网段节点拿着配置里的端口
  发第一个报文就石沉大海。`tcp_port` 仍可回退 —— 对端从种子回传的通告里学到实际端口。
- VPN 场景把虚拟网卡加入 `deny_interfaces`（默认已含常见项）。

定位单颗种子是否通：设置 →「跨网段种子」每行的 **测试** 按钮，会分别报 UDP 与 TCP 两跳结果。
跨网段最常见的故障正是「UDP 通、TCP 被防火墙挡」。种子清单改完**保存即生效**，无需重启。

## 6. 配置与数据目录

配置文件与数据库默认在系统用户配置目录（Windows 为 `%APPDATA%\SwarmLink`）：

```
%APPDATA%\SwarmLink\
  config.toml        配置（首次启动生成）
  data\app.db        聊天记录等
  identity\          节点身份
  logs\              日志
  webview\           WebView2 缓存
```

改位置有两种方式：

```powershell
# ① 环境变量
$env:SWARMLINK_DATA_DIR = 'D:\swarmlink-data'
.\bin\SwarmLink.exe

# ② 便携模式：exe 同级放一个空的 portable.mode
New-Item -ItemType File .\bin\portable.mode
```

**四个必须知道的副作用**：

1. **换数据目录 = 换节点身份**。`identity/node.key` 跟着数据目录走，换一处就会生成新的
   `node_id`，对端看到的是一个新节点，历史记录也留在旧目录。
2. **WebView2 缓存也跟随数据目录**。它默认在 `%APPDATA%\<exe 名>`，那里不可写时
   WebView2 会以 `ERROR_BUSY` 失败，且错误被 Wails 内部收尾 —— 现象就是「双击没反应」。
3. **日志有兜底位置**。`<数据目录>/logs/swarmlink.log` 写不了时退到
   `%TEMP%\SwarmLink\swarmlink.log`；启动失败对话框会写明实际位置。
4. **启动失败不再静默**。产物没有控制台（`-H windowsgui`），后端起不来时会弹原生对话框，
   内容可用 `Ctrl+C` 复制；自动化场景用 `SWARMLINK_NO_STARTUP_DIALOG=1` 关掉。

常用配置段：

| 段 | 关键项 |
|----|--------|
| `[general]` | `display_name` |
| `[download]` | `default_dir`、`auto_open` |
| `[network]` | `tcp_port`/`udp_port`（0 = 自动）、`port_fallback_range`、`interface_mode`、`allow/deny_interfaces` |
| `[discovery]` | `announce_interval`、`peer_ttl`、`max_peers`、`max_peer_list_size` |
| `[discovery.seeds]` | `refresh_interval`、`seeds_per_refresh`、`list`（`IP:UDP_PORT`） |
| `[connection]` | `idle_conn_timeout`、`max_dial_concurrency`、`max_active_conns` |
| `[transfer]` | `max_concurrent`、`chunk_size`、`window_size`、`bitmap_flush_interval` |
| `[security]` | `require_auth=true`（**保持开启**）、`encryption`（v1.1 启用，当前 `off`） |

## 7. 代码结构

```
main_wails.go    桌面外壳组合根（build tag: wails），唯一接触 Wails API 的文件
Taskfile.yml     wails3 构建任务
build/           平台构建配置与图标资源
internal/
  domain/        纯领域（零 I/O）: identity peer message group transfer protocol ports
  app/           用例编排: peer/chat/group/transfer/discovery App + Router
  adapters/      net/{tcp,udp} store/{sqlite,mem} config filesink keystore wails
  infra/         eventbus clock log fsutil
  bootstrap/     唯一组合根（GUI 装配路径）
test/
  harness/       单进程多节点装配器
  e2e/           发现/握手/单聊/幂等/传输/续传/跨网段收敛
  scale/         20 节点目录同步
frontend/
  src/           Vue3 + Pinia + TS
  bindings/      生成的绑定（已入库，勿手改）
```

**三条红线由测试强制**（`internal/archtest`，随 `go test ./...` 执行，CI 在 Windows 与 Linux 各跑一遍）：

| 红线 | 内容 |
|------|------|
| R1 | `domain/**` 禁止 import `net` / `database/sql` / `os` / Wails |
| R2 | 适配器之间禁止互引；跨模块只走 `ports` 接口或事件总线 |
| R3 | 业务代码（`app` / `domain`）禁止 `new` 具体适配器 |

新增依赖方向之前先想清楚这三条；红线测试会拦住不合规的写法，而不是靠自觉。

## 8. 构建与运行故障排查

### `wails3 build` 报 Go 版本冲突

现象：一屏 `package requires newer Go version` /
`This application uses version goX of the source-processing packages but runs version goY`。

原因：**`wails3` CLI 是用另一个 Go 版本编译的**。注意 `wails3 doctor` 里的 `Go Version`
报的是 **CLI 自己的构建版本**，不是 PATH 里的 Go —— 以它为准。

```powershell
go version                                 # 本机 Go
go version (Get-Command wails3).Source     # CLI 的构建版本，两者应一致
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.29
```

多版本 Go（vfox / asdf / scoop）下格外容易踩：`go install` 把 CLI 装进**当时激活的那个
Go 的 `GOPATH\bin`**，切换 Go 版本不会更新它，旧副本仍留在 PATH 上
（`Get-Command wails3 -All` 可列出全部）。用 `pack.ps1` 构建可绕开这个问题。

### 报 `GOROOT` 与实际使用的 go 不一致

现象：`compile: version "go1.25.5" does not match go tool version "go1.26.3"`。

原因：`go.mod` 要求 1.26，用 1.25 编译会触发 `GOTOOLCHAIN=auto` 下载第二份工具链。
解决：直接用 1.26 以上的 Go，或走 `pack.ps1`（已处理）。

### `pack.ps1` 被执行策略拦住

现象：`未对文件进行数字签名`。脚本没有「来自互联网」标记，`Unblock-File` 解决不了。

```powershell
# 只对这一次调用生效
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\pack.ps1 windows build

# 或当前 shell 临时放宽（关窗即失效，不写注册表）
Set-ExecutionPolicy -Scope Process Bypass
```

不要用 `-Scope CurrentUser Unrestricted`：它是持久的，且比 `RemoteSigned` 弱。
若 `CurrentUser` 已是 `RemoteSigned` 却仍被拦，说明当前 shell 的有效策略更严，
用 `Get-ExecutionPolicy -List` 看是哪个作用域收紧了。

### 构建"成功"但程序只有 2.4 MB

漏了 `-tags wails`，产物是占位程序。用 `pack.ps1`，或手工：

```powershell
wails3 generate bindings -f "-tags wails" -clean .
wails3 build -tags wails
```

### dev 窗口显示「HTTP ERROR 502」/ wails.localhost 无法处理此请求

现象：`start_dev.bat` 起来后，窗口里是 Edge 的 502 错误页，但终端里 Vite 明明打印了 `ready in xxx ms`。

原因：Vite 的 `server.host` 默认是 `localhost`，Node 17+ 在 Windows 上会把它解析成 `::1`，
于是 Vite 只监听 `[::1]`；而 Wails dev 的 asset server 连的是 `127.0.0.1`，请求被拒后转成 502。

一条命令确认：

```powershell
curl.exe -s -o NUL -w "IPv4=%{http_code}`n" --max-time 3 http://127.0.0.1:9245/
curl.exe -s -o NUL -w "IPv6=%{http_code}`n" --max-time 3 "http://[::1]:9245/"
# IPv4=000 而 IPv6=200 → 就是这个症
```

解决：`frontend/vite.config.ts` 里已显式 `host: '127.0.0.1'`，不要删。改完 Vite 会自动重启，
窗口点「刷新」即可。

另一类无害的 502：**Vite 比窗口启动慢**。刚打开的一两秒内点刷新就好，不是缺陷。

### 重跑 dev 时报 `Port 9245 is already in use`

上一次的 dev 没退干净（`wails3 dev` 的 background 任务可能留下 Vite 孤儿进程）。
`frontend/vite.config.ts` 与 Taskfile 都用了 `strictPort`，端口被占时 Vite **直接退出**，
不会自动换端口 —— 表现同样是 502。先清掉残留：

```powershell
Get-NetTCPConnection -LocalPort 9245 -State Listen | Select-Object OwningProcess
Stop-Process -Id <上面的 PID>
```

### 双击没反应

见 §6 第 2、4 条：多半是数据目录不可写导致 WebView2 起不来，看启动失败对话框与日志兜底位置。

## 9. 已知限制

- 空闲回收后连接不再可用，不主动重连，下次发消息才按需拨号（首条消息多一个 RTT）；
- 群聊对离线成员由发送端重发（退避上限 5 分钟），全员确认后才出队；
- 托盘气泡与提示音**当前仅 Windows**；
- 原生文件对话框在浏览器预览模式下降级：文件给路径输入框，文件夹与图片只给提示；
- 未接入混沌测试（随机杀连接）的自动化 CI 任务。
